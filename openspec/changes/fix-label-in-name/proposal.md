# Proposal

## Why

Dependabot PR #34 bumps `@axe-core/playwright` 4.13.0 → 4.14.0. In axe-core 4.14.0 the `label-content-name-mismatch` rule (WCAG 2.5.3 Label in Name, impact `serious`) is no longer tagged `experimental`, so it now runs under the `wcag21a` tag the E2E scans use. Several interactive elements set an `aria-label` that does not contain their visible text, so the `/topology` scan and the chaos-scenario journey fail. These are real defects: a speech-input user who says "click LOD Detail" cannot activate a button whose accessible name is "Toggle Level of Detail Grouping".

## What Changes

- Bump `@axe-core/playwright` to `^4.14.0` in `apps/web/package.json`, keeping the caret style the other devDependencies use; lockfile regenerated by pnpm. No other dependency changes. Dependabot PR #34 stays open and untouched; after this merges, Dependabot rebases it with its remaining updates.
- Make the accessible name of every interactive element with visible text contain that text as a contiguous word sequence, starting with it where the element has extra context:
  - LOD toggle in `CanvasToolbar.tsx`.
  - Node cards in `BaseNodeCard.tsx` (metrics strip is visible text inside a `role="button"`).
  - RPS pill on edges in `TrafficEdge.tsx` (visible `1.2k rps`, name uses a differently formatted number).
  - Expand/collapse button in `GroupNode.tsx` (visible `N nodes`, name "Expand service group").
  - `EvidenceChip.tsx` (visible kind prefix, e.g. `SERVICE`, is missing from the name).
  - Any further element the 4.14 scan reports.
- Context that is not visible (health, upstream/downstream counts, protocol) stays after the visible text in the name, or moves to `aria-describedby`.
- Component tests that fail when an element's accessible name stops containing its visible text.
- The `label-content-name-mismatch` rule stays enabled; no visible text is hidden from assistive technology.
- Report only, no fix: why the chaos E2E test's retry gets a non-OK response from `POST /api/v1/simulation/scenarios/request-storm/activate`.

## Capabilities

### New Capabilities
- `accessible-names`: how interactive UI elements in the web app expose accessible names relative to their visible text (WCAG 2.5.3), and how this is enforced in tests.

### Modified Capabilities
None. `openspec/specs/` has no existing capabilities.

## Impact

- Code: `apps/web/src/components/topology/{CanvasToolbar,BaseNodeCard,TrafficEdge,GroupNode}.tsx`, `apps/web/src/components/insights/EvidenceChip.tsx`, possibly others found by the scan.
- Tests: new or extended files under `apps/web/tests/components/`. Existing E2E selectors that match by accessible name (`getByRole(..., { name })`, `getByLabel`) may need updating; the E2E axe scans themselves stay unchanged.
- Dependencies: `@axe-core/playwright` (dev dependency only) and its transitive `axe-core`, both 4.14.0.
- Screen reader output changes wording for the listed elements; no visual change, no API or contract change.
- Docs: `docs/ARCHITECTURE.md` only if a written accessibility convention changes.
